# Iterations

Each loop records the expectation before checking, what broke, and the fix. A result counts only after a check that could have failed has passed.

## Loop 1 — dollar-diff test harness (2026-10-21)
- **Expected:** replaying each task's gold actions as an "agent" trajectory gives zero dollar loss, and injected mistakes give the injected loss.
- **What broke:**
  1. The first real-task tests used airline tasks 0–4. **None of them contains a money-moving action** (task 0 has no actions at all), so "zero loss" passed whatever the code did. The tests were vacuous.
  2. The hand-built replay had blank tool outputs. tau2's strict replay rejects those, so the replay never ran on tasks that change state.
- **Fix:**
  - Tool outputs are now generated by executing the actions in a scratch environment.
  - Tests use the first tasks whose gold actions move money.
  - A guard asserts that the replay changed the DB.
  - A suite-level check requires at least 7 of the first 10 money tasks to change a money position.
  - Two deliberately wrong real-task cases were added: an extra $100 certificate (must give exactly $100 first-party loss) and an unwarranted cancellation (must give a positive loss).
- **Also found:** task 12's gold action adds *free* bags, so it moves no money. The first guard ("money must move") wrongly failed on it and was relaxed to "the DB must change".
- **Result:** 15/15 tests pass.
- **Still open:** the dollar model values money only. Wrong flights or seats with no price change score $0 even when the DB doesn't match. Report these separately as non-monetary failures.

## Loop 2 — pilot batch 1 (5 tasks × 3 runs) and loss classification (2026-10-21)
- **Batch:** tasks 1, 7, 8, 11, 14 × 3 runs. All 15 stopped normally with 0 infrastructure errors. Pass^1 0.60, pass^2 0.47, pass^3 0.40 (0.6³ = 0.22 if independent, so failures cluster by task). DB match 11/15. Cost $0.243 total ($0.010–0.034 per run); token cost matched tau2's per-message cost on every run.
- **Expectations, checked:**
  1. Costs were in range ✓
  2. No run with a matching DB showed $ ✓
  3. ≥1 failure ✓
  4. Clustering: suggestive only, as 5 clusters is too few
  5. COMMUNICATE-only failures had $0 ✓
- **What broke:** v1 of the dollar diff netted balances and reported 4 "loss events" ($500, $500, $2,046 and $296). Reading the transcripts showed three were **the agent not doing something**: two missed bookings (task 8) and a change never requested (task 14). The fourth was a partial job that was handed to a human. A missed sale is not a payout. The independent reviewer reached the same finding (REVIEW.md #2), and also found gift-card downgrade refunds double-counted (#1).
- **Fix:** dollar diff v2 classifies every difference by transaction:
  - **payout_loss:** over-refund, undercharge, unwarranted compensation
  - **customer_harm:** overcharge, wrongful booking
  - **omission:** missed sale, withheld refund, change not made, withheld compensation

  Base severity = payout_loss + customer_harm; omissions are recorded separately. There are new exact-amount tests, including the task-11 $5,244 gift-card downgrade and the task-8 missed booking. 22/22 pass.
- **Re-scored result:** **0 insured loss events in 15 runs. All 6 failures were omissions** ($348–3,180 each, 3 of them handed to a human).
- **Failure attribution (transcripts read):**
  - task 8 ×2: mixed. The simulated customer insisted on seat assignments that no tool supports, and the agent handed off.
  - task 14: the **user simulator** ended the call without requesting the change.
  - task 7 trial 2: **agent**. It cancelled one reservation and handed the other to a human.
  - task 7 ×2: COMMUNICATE only (one figure never stated), so the agent, at $0.
- **Implication:** with 0 events, the rule-of-three 95% upper bound on the loss-event rate is about 3/15 = 20% (naive), and wider with clustering. The commission peril is rare on these tasks. It mainly lives on tasks where the correct action is refusal (REVIEW.md #5), so the next batch must cover them.

## Loop 3 — breadth batch (planned): many tasks, few repeats
- **Why:** reviewer #4. 5 clusters can't estimate the ICC, and the hand-picked tasks bias q.
- **Design:** a seeded random 25 of the 50 airline tasks × 2 runs = 50 runs, about $0.9. This deliberately includes tasks whose correct action is refusal or no action.
- **Expectations, written before running:**
  - ≥10 failures
  - the commission share of failures is low (<25%)
  - the loss-event rate is at most 10%
  - the failure ICC across 25 clusters is clearly above 0
- **Loop 3 result:** 50 runs, 9 failures (18%; Wilson 10–31%), failure ICC 0.61, 1 raw commission divergence and **0 insured loss events**. The expectations held: ≥10 failures ✗ (9, close), commission share low ✓, loss rate ≤10% ✓, ICC clearly above 0 ✓.
- **What broke:** task 42's $4,418 "over-refund" was a **customer-requested, policy-permitted** business-class cancellation. The user simulator said the extra trip was "from my assistant's mess". A divergence from gold is not a wrongful act.
- **Fix:** `policy.py` checks the tau2 cancellation rules (24 h, business class, airline-cancelled flight; insurance is "uncertain") and splits wrongful payouts from permitted divergences. 6 new tests; 28/28 pass. Re-scored: 0 insured events in 65 runs.

## Loop 4 — projection (step 7)
- **Expected:** the τ² airline clustering ceiling makes a credible frequency impossible by repetition.
- **Checked:** with ρ = 0.59, the ceiling is about 85 effective runs. No scenario in `results/pilot/projection.json` is feasible with 50 tasks. The loosest (±20%, q = 20%) needs 484 distinct tasks.
- **Result:** the main-run recommendation shifts from "more repeats" to "more distinct tasks + refusal/adversarial tasks + credibility blending". Iteration cap reached (4 loops), so the report follows.

## Phase 0, loop 1: smoke test, one cell (q = 5%, ICC 0.3, parent share 0.9, 2,000 runs, 30 reps)
- **Expected:** see EXPERIMENTS.md Phase 0.
- **Observed:**
  - T0 naive: −16% bias (as predicted)
  - T1 IS: +1.7% bias, coverage 0.90 (as predicted)
  - T1-var: coverage 0.83 (under-covers, as predicted)
  - **T2 Bühlmann: +12% bias**
  - **T3 near-miss with R correct: −28%**
  - **T4 control variate: −13%**
- **Diagnosis:**
  - **T4 was a bug in the truth.** The known score mean omitted the noise and clipping applied to the scores. Fixed.
  - **T2 had a real pitfall.** The Bühlmann complement (collective mean) was the IS sample's exposure-weighted mean, which oversampling inflates. Fixed to the W-mixed stratum mean. Kept as a documented lesson: credibility complements must be mix-consistent.
  - **T3 is a real limitation, not a bug.** Near-misses saturate at 1 per run, so p̂ = NM/R is biased downward whenever R·p isn't small (refusal p ≈ 18% → R·p capped). Reported as a result, not "fixed".

## Phase 0, loop 2: full grid (36 cells × 150 reps), Wald intervals
- **Result:** T1, T2 and T4 are unbiased (median |bias| ≤ 1.1%) but **under-cover** (0.85–0.88, worst at 500 runs). Pure premium covers 0.84. Near-miss fails everywhere.
- **Fix:** log-scale delta-method intervals (suited to rare positive rates); Bühlmann bootstrap B 60 → 200.

## Phase 0, loop 3: log intervals + capped pure premium
- **Coverage medians:**
  - T1: 0.89 (0.85 at 500 runs)
  - T2: 0.87 (0.81 at 500 runs)
  - T4: 0.88
  - uncapped pure premium: 0.83 (fails)
  - **pure premium capped at a $2,000 basic limit: 0.87 (0.89 at ≥2,000 runs), passes**
- **Verdict:**
  - **keep** T1, T2 (≥2,000 runs) and T4, and price a **capped** basic-limit pure premium
  - **drop** T3 near-miss (−21% bias even with the correct R; saturation)
  - T1-var confirms that errors must be clustered at the parent level
- Iteration cap: 3 of 4 used in phase 0.
